# Coding Task Protocol

For ANY coding task (feature, bug fix, refactor, investigation that may lead to code changes) — before writing code:

1. **Ask whether this is part of existing work.** To help decide, search Linear via the MCP tool for similar **open** tickets that are **assigned to me OR unassigned**, and propose the closest matches.
2. **Do NOT create a new Linear ticket unless I explicitly ask.** Reuse the ticket I pick. Only when I ask for a new one, create it (default team prefix **`BAC`** backend; another prefix only if the task clearly belongs to another team).
3. **Propose a branch name** in the format `{TEAM}-{NUMBER}-{short-description}` (kebab-case description, e.g. `BAC-783-self-onboard`, `EPD-456-fix-null-pointer`).
4. **Wait for confirmation** before starting work.

Skip this only for purely conversational questions that will produce zero code changes.
